# Generate: Sprint Page (output: sprint-{{n}}.html)

**Prompt version:** 1.0

## Role
You are a delivery lead producing a visual, at-a-glance status page for the sprint that was just planned.

## Where this fits — not on-demand, a required link in the chain
Unlike `11-dashboard/1-generate-dashboard.md` (on-demand, run whenever), this prompt always runs immediately after `7-sprint-planning/1-sprint-planning.md` finishes — it's a mandatory step in the sequence, not an optional utility. It can still be re-run later by hand if the developer wants a refreshed snapshot mid-sprint, but that's a bonus, not its trigger.

## Scope — markdown-sourced only, not a code-verification tool
Same trust boundary as the dashboard: every number and status on this page comes from `project-docs/claude-docs/`'s own tracking files — never from reading application source code. This page is exactly as trustworthy as the markdown a developer keeps current.

## Objective
Read the sprint file just created (or specified) plus its referenced tasks/epics, and produce one self-contained static HTML file for that single sprint — a header, stat tiles, and a task table, viewable directly in a browser with no server or build step.

## Inputs
- `project-docs/claude-docs/sprints/sprint-{{n}}.md` — the sprint just planned: goal, milestone/epic references, status, ordered task list, Assigned To column (if multi-developer), parallel-safe batch grouping (if used).
- `project-docs/claude-docs/plan/task-list.md` — full detail (description, estimate, notes, blocking reason, file/folder footprint) for every task listed in the sprint.
- `project-docs/claude-docs/plan/epics.md` — epic names, status, Design Status (if set), for context on which epic each task belongs to.
- `project-docs/claude-docs/plan/raid-log.md` and `tech-debt-register.md` — filtered to items that explicitly name this sprint.
- `CLAUDE.md` / `project-docs/sot-docs/index.md` — project name.

## Instructions
1. Read the sprint file and every task it lists from `task-list.md`.
2. **Header.** Project name, sprint number, sprint goal, milestone + epic references, sprint status badge, generation timestamp.
3. **Stat tiles** (a row of compact cards):
   - **Sprint Progress** — % of this sprint's tasks `Done`, subtext with the raw fraction (e.g. "5 of 8 tasks").
   - **In Progress** — count of tasks currently `In Progress`.
   - **Blocked** — count of tasks `Blocked`, subtext naming the count with a blocking reason recorded.
   - **Available** — count of tasks not yet claimed.
   - Every tile: number first (large), label, one-line subtext — no tile without a subtext explaining what it's counting.
4. **Task table.** One row per task in the sprint, in the sprint file's own order: ID, short description, status badge, point/effort estimate if tracked, **Assigned To** (omit column entirely for solo-developer projects), blocking reason inline if `Blocked` (from `task-list.md`'s notes, not a bare restatement of the badge). If the sprint file groups tasks into parallel-safe batches, group the table visibly by batch, not one flat list.
5. **Notes/blockers section.** One entry per open `raid-log.md`/`tech-debt-register.md` item that explicitly names this sprint, written as a real sentence with whatever concrete detail the source file contains — not invented beyond what's recorded. Omit this section entirely if nothing names this sprint.
6. **Status legend.** Same color mapping as `11-dashboard/1-generate-dashboard.md` for consistency: `Done`/`Complete` = green, `In Progress` = blue, `Blocked` = red, `Available`/`Not Started` = grey, `Claimed` = amber, `Cancelled` = strikethrough grey.
7. **Footer.** "Generated by `7-sprint-planning/3-generate-sprint-page.md` from `sprint-{{n}}.md` and its referenced task/epic files · re-run any time for a current view." State plainly this is a Claude-run, on-demand-when-re-run regeneration, not an automated pipeline.

## Visual/technical requirements
- Fully self-contained: inline `<style>` only, no CDN links, no external fonts/images — must open correctly from a plain double-click, offline, no dev server.
- Support both light and dark viewing via `prefers-color-scheme`.
- Read-only and static — no edit forms, no write-back. Status changes happen by editing the source markdown and re-running `1-sprint-planning.md`/`8-implementation/` prompts, then re-running this prompt.
- Optional `<meta http-equiv="refresh" content="600">` if the developer tends to leave the page open — this is a flat task table with no expand/collapse state to preserve, so no `sessionStorage` handling is needed the way the dashboard needs it.
- Write to `project-docs/claude-docs/sprints/sprint-{{n}}.html`, overwriting any previous version for this sprint.

## Output
- `project-docs/claude-docs/sprints/sprint-{{n}}.html` — regenerated in full each run.
- After writing the file, tell the user its full path and how to view it: open it directly in any browser (double-click, or drag into a browser window) — no server or build step needed.

## Guardrails
- Never read or parse actual application source code — every figure comes from `project-docs/claude-docs/` markdown only.
- Never hand-edit an existing `sprint-{{n}}.html` incrementally — always regenerate from the current sprint/task/epic files.
- Don't add write/edit interactivity — status changes belong in the source markdown, not the HTML.
- Don't pull in any external script/style/font — must render correctly with no network access.
- Don't state or imply a number is more certain than its source file supports.

## Completion Checklist
- [ ] Sprint file and every one of its listed tasks read fresh from `task-list.md`
- [ ] All 4 stat tiles present, each with a subtext explaining its number
- [ ] Task table reflects the sprint file's own order and batch grouping (if used)
- [ ] Notes/blockers section reports only what source files state, or is omitted if none apply
- [ ] Status colors match `11-dashboard/1-generate-dashboard.md`'s legend
- [ ] File is self-contained (no external requests) and readable in both light and dark OS themes
- [ ] Written to `project-docs/claude-docs/sprints/sprint-{{n}}.html`
