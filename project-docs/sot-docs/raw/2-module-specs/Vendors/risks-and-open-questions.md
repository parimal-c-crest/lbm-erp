# Vendors — Risks & Open Questions

Source: `docs_from_blueprint/module/Vendors/09-risks-and-open-questions.md`, itself consolidated from
`blueprint/module/Vendors/07-risk-findings.md` and `08-consolidation-review.md`. This is the highest
Critical-finding *density* of any module blueprinted in the source series so far: 5 Critical findings in a
37-file module — tying the largest module blueprinted (209 files) at the same absolute Critical count, in
roughly one-sixth the file surface.

| VEN-RISK-001 | `SaveVendorLinecodeDescription.php`'s missing vendor-scoping has system-wide, cross-module blast radius — an ordinary per-vendor line-code-description edit silently overwrites the same literal line code's description for every other vendor and every downstream consumer (Products' picker, the line code's owning module's own edit/list views, the shared line-code listing widget), deterministically, on every save, with no attacker input required. **A note on the "9+1 SQL injections" figure vs. the 5-Critical count above**: the source material's own
header describes "eight confirmed injection points across seven files, plus one more in a directly-related
Purchase-Order-module file" — a **statement-level** count (each individually-vulnerable SQL statement
counted separately). The Risk-Register severity tiers above count at **finding/file level** instead: 4
Critical + 3 High = 7 distinct SQL-injection findings (6 in the module's own files, 1 in the
Purchase-Order-module file), plus VEN-RISK-001 (Critical, but explicitly **not** an injection — its value
binding is confirmed parameterized; the defect is scope-correctness) = 5 Critical total, not 10. Both
counts are internally consistent readings of the same underlying findings at two different granularities —
flagged here since a reader taking the statement-level framing as a severity-tier count would overstate the
Critical-tier count by roughly a factor of 2.

## Verdict on this module's density

The source's consolidation pass frames this module's risk profile explicitly against the rest of the
series: Vendors is 37 files; the largest module blueprinted so far is 209 files — nearly six times larger.
Both land at the same absolute Critical-finding count: 5. Measured as findings-per-file, Vendors' Critical
density (5/37 ≈ 0.135) is nearly six times the larger module's (5/209 ≈ 0.024) — not because Vendors' code
is more numerous or more complex, but because a supplier-master module with a comparatively narrow,
purchasing-scoped file set still accumulated the same absolute count of unescaped-splice SQL statements the
larger module needed nearly six times the files to reach. This is flagged in the source as a "patch the
legacy system now" cluster, independent of any rewrite timeline — VEN-RISK-001 through VEN-RISK-008 need
legacy-system remediation regardless of when a rewrite ships.
